# Review response (ha-also 0.2.2)

Source: two-model semantic review of the first HACS release (20 issues: 4 High, 9 Medium, 7 Low). Each
finding was checked against the actual code first; the table says what was done and which test proves
it. With the integration code reverted to 0.2.1 (and pyalso 0.2.2 left in place), 29 of the new or
changed tests fail, including every regression test named below (a few fail at import because they use
a new name, which is also a failure on the old code).

Totals: 20 findings. Fixed: 18 (3 High, 9 Medium, 6 Low). Documented by decision, not fixed: 2 (#4 High,
#18 Low). Not-a-bug: 0.

## Behaviour changes users can notice

* Entities no longer stay available on a connected-but-silent stream while REST is down; they flip
  at the freshness deadline.
* A stream that gave up stays off until the entry reloads; diagnostics say so.
* A battery packet WITHOUT a source time can no longer outrank a timestamped REST value (the real
  service always stamps battery packets; this only affects hand-built data).
* The charge-state sensor lists three more neutral options (`unknown_0`, `unknown_2`, `unknown_4`).
* New disabled-by-default diagnostic sensors for stream-only values; a repair issue appears when
  the token write fails; the minimum Home Assistant version is 2025.12.0.
